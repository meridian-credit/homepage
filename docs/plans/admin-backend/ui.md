# 관리자 화면 설계 (2026-10-12 다시 그림)

주인 평: 「보기가 너무 어렵게 되어 있다. UI/UX 가 최악이야. 확장성, 무엇이 자주 쓰이고(클릭되고) 유지보수될지를
고려해서 원점에서 만들어 줘.」 그래서 두 디자이너(Claude Opus 5.5, codex gpt-6.1-sol)가 서로를 보지 않고 각자
처음부터 설계하고 시안(HTML)을 만들었다. 그 둘을 화면으로 비교해 하나로 정하고 구현했다.
시안과 두 설계서 원문은 `temp/admin-redesign/`에 있다(저장소에 넣지 않는 작업 폴더).

## 정한 것

**Claude 안을 바탕으로 삼았다.** 두 안이 같은 데 닿은 곳이 많았고, 갈린 곳에서는 Claude 안이 「가끔 들어와 한 가지를
빨리 끝낸다」는 쓰임에 더 맞았다.

| | 내용 |
|---|---|
| **같이 닿은 것** | 왼쪽 메뉴(자주 쓰는 순서) · 달별로 묶은 세무 일정과 D-day · 목록에서 그 자리에서 펴 고치기 · 화면 아래 저장 막대 · 각 화면에서 그 종류의 변경 기록으로 가는 단추 · 되돌리기 전에 달라지는 점 보이기 · 되돌리기도 미리 본 판 번호로만(그 사이 저장을 덮지 않게) · 항목마다 저장하지 않고 목록 통째로 · 끌어 옮기기 대신 위 · 아래 단추 · 새 npm 의존성 없음 |
| **codex 안에서 가져온 것** | 저장하는 동안 편집 칸을 잠근다(보내는 사이 친 글이 저장 결과에 덮여 사라지지 않게). 되돌리기 판 번호 확인(이것은 두 안이 같이 짚었다) |
| **버린 것** | codex: 늘 떠 있는 저장 막대(바뀐 것이 없을 때도 자리를 차지하고 내용을 가린다) · 오른쪽 도움말 칸(읽히지 않는 글) · 지우기 확인 창(저장 전이라 「지울 예정 + 되살리기」가 빠르고 안전하다) · 저장 전 미리 보기 창(저장 = 반영이고, 저장 뒤 「사이트에서 보기」 한 번이면 된다). Claude: 「명령 팔레트 · 알림 센터 · 다크 모드」는 처음부터 넣지 않았다 |

## 화면

- **틀.** 왼쪽 메뉴: 홈 / 사이트 내용(세무 일정 · 자주 묻는 질문) / 변경 기록. 바닥에 사이트 열기, 이름, 로그아웃.
  960px 아래에서는 머리줄 [≡] 이 같은 메뉴를 시트로 연다. 세무 일정이 30일 안에 바닥나면 메뉴에 점이 붙는다.
- **홈.** 숫자판이 아니다. 손볼 일 하나와 단추 하나: 반영 실패 → 세무 일정 바닥 → 30일 안에 바닥 → 「지금 손볼 일은
  없습니다. 11월 15일부터 이 화면에 알림이 뜹니다」. 그 아래 지금 사이트에 보이는 일정, 사이트 내용, 최근 변경.
- **세무 일정.** 숫자판 셋(다가오는 일정 · 일정이 채워진 날 · 국세청 확인일 [오늘 확인함]). 달별 표, 달마다 국세청
  표 링크, 목록 끝에 다음 빈 달의 「아직 없음 — N월 일정 추가」 칸. 새 일정 칸은 목록 위에서 연달아 넣는다.
  줄을 누르면 그 줄이 입력칸이 된다. 지난 일정은 접어 둔다.
- **자주 묻는 질문.** 질문 + 답 첫 줄 목록. 누르면 그 자리에서 펼쳐 고친다(한 번에 하나). 「순서 바꾸기」를 켜면
  질문만 남은 줄과 위 · 아래 단추. 마지막 문답은 지울 수 없다.
- **변경 기록.** 날짜별, 종류로 거르기(주소 `?type=`). 한 줄 요약은 저장된 글이 아니라 전 · 후를 다시 비교해 만든다.
  펴면 바뀐 점(긴 답은 달라진 낱말만 칠한다)과 [이 저장 이전으로 되돌리기]. 맨 아래 「사이트에 다시 반영」.
- **로그인.** 비밀번호 보기, Caps Lock 안내. 저장 막대의 「다시 로그인」으로 오면 끝나고 그 화면으로 돌아간다.
  돌아갈 곳(`?next=`)은 이 앱 안의 경로만 받는다. 제어 문자를 거절하고 URL 로 풀어 같은 곳인지 본다 — 브라우저가 탭을
  지워 「/<탭>/다른.호스트」가 다른 호스트로 가는 길을 리뷰가 찾았다(시험 있음).

## 저장의 일생 (모든 종류가 같다)

작업본을 고친다 → 저장 막대 「저장하지 않은 변경 N건 · 요약」 → [저장하고 반영] 또는 Ctrl+S →

| 결과 | 화면 |
|---|---|
| 저장 · 반영 | 막대가 초록 「저장했습니다」, [사이트에서 보기], 8초 뒤 닫힘. 경고(30일 · 지난 일정)는 한 줄 붙임 |
| 고칠 곳 있음 | 막대가 빨강, [고칠 곳 보기]가 첫 칸을 펴고 초점을 옮김. 칸 아래 빨간 글 |
| 저장은 됐지만 반영 실패 | 서버가 기억한다(`content_meta` 의 `admin.publishFailed`). 모든 화면 위 띠와 홈에 [다시 반영] |
| 다른 곳에서 먼저 저장 | 덮어쓰지 않는다. 창: 누가 · 언제, 저장하지 못한 내 변경, [내 변경 복사] [최신 내용 불러오기] → 새로 연 화면 위에 내 변경을 남김 |
| 연결 끊김 · 관리자 재배포 | 막대 「저장하지 못했습니다」[다시 시도]. 적던 글은 화면과 이 기기에 남음 |
| 로그인 끝남 | 액션은 로그인 화면으로 보내지 않고 `signed-out` 으로 답한다. [다시 로그인] → 같은 화면 → 「이 기기에 남은 변경」 [이어서 고치기] |
| 새 일정 칸에 적고 [목록에 추가]를 안 누름 | 저장을 막고 그 칸으로 초점. 저장하며 칸이 닫히면 적은 것이 소리 없이 사라지기 때문 |
| 변경 취소 | 8초 동안 [되살리기] |

이 기기 보관: 바뀐 것이 있으면 `localStorage` 의 `meridian-admin:draft:<종류>` 에 작업본과 그 판 번호를 둔다.
이어서 고치면 그 판 번호로 저장하므로, 그 사이 누가 저장했으면 충돌로 막힌다. 저장 · 변경 취소 · 로그아웃이 지운다.
「남아 있습니다」 띠에 답하지 않고 새로 고치면 새 것을 보관한다(가장 최근 작업이 이긴다). 그 상태에서 [이어서 고치기]를
누르면 방금 고친 것은 [되살리기]로 돌아올 수 있다. 충돌 뒤 남기는 「내 변경」에는 새 문답의 답까지 다 들어간다.

알고 있는 빈틈: 서버에서 세션을 지운 뒤(`user.mjs passwd · remove`) 저장하면 Better Auth 가 쿠키를 지우고 Next 가 화면을
다시 그리며 로그인 화면으로 보낸다(`?next=` 없이). 적던 내용은 이 기기에 남아, 다시 들어와 그 화면을 열면 권한다.

## 코드의 자리

```
admin/src/
  content/registry.ts        종류 목록: 이름 · 주소 · 아이콘 · 무리 · 공개 쪽 · 「어디에 나오나」. 메뉴 · 홈 · 기록 거르기가 읽는다
  content/<종류>.ts          zod 규칙(브라우저와 서버가 같이) · 한도 · describe(전, 후) → { changes, summary }
  content/history.ts         기록 한 건 → 제목 · 한 줄 · 바뀐 점 · 되돌림 여부
  editing/use-editor.ts      저장 흐름(위 표 전부). 종류마다 다른 것은 config 로 받는다
  editing/save-bar.tsx       저장 막대 + 충돌 창
  editing/editor-notices.tsx 이 기기에 남은 변경 · 충돌 뒤 내 변경 띠
  ui/                        틀(shell) · 쪽 머리 · 반영 실패 띠 · 바뀐 점 목록 · 아이콘
  app/(app)/<종류>/          page.tsx(서버: 읽기) + <종류>-editor.tsx(클라이언트: 그 종류의 모양)
  app/actions.ts             저장 · 되돌리기 미리 보기 · 되돌리기 · 다시 반영. 모두 처음부터 로그인과 입력을 다시 본다
  app/admin.css              토큰과 부품. 번호 붙은 구역(1 토큰 … 18 좁은 화면). Tailwind 를 쓰지 않는다
```

스키마로 폼을 찍어 내는 범용 편집기는 만들지 않았다. 종류마다 모양이 다르고(표 · 목록 · 한 벌 · 문서), 공용 부품 +
손으로 짠 본문이 8종까지는 더 싸고 읽기 쉽다.

## 콘텐츠 종류를 더할 때

1. `src/lib/content/schema.ts` 의 `MIGRATIONS` 끝에 표를 더한다(지우기 · 이름 바꾸기 금지). `META` 에 판 번호 키.
2. 공개 쪽 읽기: `src/lib/content/read.ts`.
3. `admin/src/content/<종류>.ts`: zod 규칙 · 한도 · `describe()`.
4. `admin/src/lib/content.ts`: 읽기와 쓰기(판 번호 확인 → 바꾸기 → 기록, 한 트랜잭션). 기록 `kind` 에 종류를 더한다.
5. `registry.ts` 에 한 줄. `content/history.ts` 의 `describeEvent` 와 `actions.ts` 의 되돌리기에 갈래 하나.
6. `app/(app)/<종류>/page.tsx` + 편집 본문. `useEditor` · `SaveBar` · `EditorNotices` 로 짠다. 모양에 맞는 방식만:
   짧은 줄 여럿은 그 줄 자리에서, 긴 항목은 그 자리에서 펼침, 한 벌은 바로 양식, 글처럼 많고 긴 것은 따로 쪽.
7. `actions.ts` 에 저장 액션.
8. e2e 셋을 복사해 고친다: 저장하면 공개 쪽에 나온다 / 틀린 입력은 막고 그 칸을 알린다 / 먼저 저장된 것을 덮지 않는다.

그러면 메뉴, 홈의 「사이트 내용」, 변경 기록과 되돌리기, 반영 실패 띠, 이 기기 보관, 떠날 때 경고, Ctrl+S 가 따라온다.
글(3단계)만 저장이 「초안 저장 / 발행」으로 갈린다 — 그때 저장 막대의 문구와 상태를 하나 더한다.

## 주인에게 물은 것 (2026-10-12 답)

1. 세무 일정이 30일 아래로 남으면 메일로도 알릴까요? → **아직은 괜찮다.** 관리자 홈의 알림만 둔다.
2. 로그인 유지 7일을 늘릴까요? → **30일, 2단계 인증 없이.** `admin/src/lib/auth.ts` 의 `session.expiresIn`. 하루에 한 번 이상 쓰면 다시 30일로 늘어난다.
3. 화면에 이름(「박민상 님」)을 보일까요? 지금 계정은 아이디만 있습니다. → **주인이 확인 뒤 알려 주기로.**
4. 비밀번호 바꾸기를 화면에 둘까요? 지금은 서버에서만. → **주인이 확인 뒤 알려 주기로.**
