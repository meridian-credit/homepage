## 1. 무엇을 만드나

**만든다**

| 기능 | 내용 |
|---|---|
| 글 목록 | 상태(전체 · 게시 · 초안 · 휴지통), 갈래, 제목 · 주소 · 키워드 검색. 「검토 120일 지남」 · 「고친 내용 미게시」 표시 |
| 새 글 · 편집 | 위지윅 본문(Milkdown) + 오른쪽 칸에 글 정보. 본문은 Markdown 으로 저장한다 |
| 초안과 게시본 | 게시한 글을 고쳐도 [변경 게시]를 누르기 전에는 사이트가 그대로다. 「저장」은 초안만 바꾼다 |
| 게시 전 검사 | 막는 것(오류)과 확인하면 넘어가는 것(경고)을 나눠 보인다. 각 줄에서 그 칸으로 간다 |
| 미리 보기 | 저장한 초안을 공개 사이트와 똑같은 화면으로 연다. 1시간 동안만 열리는 서명된 주소다 |
| 내리기 · 휴지통 | 게시한 글을 내리면 공개 주소가 404 가 된다. 지우기는 휴지통으로 가고, 거기서 되살리거나 완전히 지운다 |
| 사진 | 본문 사진과 표지. 끌어 놓기 · 붙여넣기 · 단추로 올린다. WebP 로 다시 굽고 위치 정보(EXIF)를 지운다. 사진 설명(대체 글)을 단다 |
| 변경 기록 | 글마다 남는다. 「그 저장 이전으로」 되돌리면 초안이 돌아가고, 게시는 따로 누른다 |
| 이 기기 보관 · 충돌 · 떠날 때 경고 · Ctrl+S | 일정 · FAQ 와 같은 저장 흐름(`use-editor.ts`)을 글마다 쓴다 |
| 게시 확인 | 게시 · 내리기 뒤 사이트를 실제로 열어 바뀌었는지 본다. 안 바뀌었으면 모든 화면에 경고가 남는다 |
| 홈 | 홈에 초안 · 미게시 변경 · 검토 120일 지난 글 |

**만들지 않는다 (까닭)**

- **예약 게시.** 정해진 시각에 게시하려면 서버에서 도는 작업이 하나 더 있어야 한다. 글이 한 달에 몇 편이면 그 시각에
  [게시]를 누르는 편이 싸다.
- **역할(편집자는 초안까지).** 계정이 하나뿐이고 주인이 아직 정하지 않았다(README §7-3). 지금은 로그인한 사람이 모두
  게시한다. 정하면 게시 · 내리기 액션 둘에 검사 하나를 더하면 된다.
- **사진 보관함 화면(쓰이지 않는 사진 지우기).** 사진은 내용 해시로 이름을 붙여 다시 쓰고, 글 수십 편이면 다 합쳐 수십
  MB 다. 커지면 그때 만든다.
- **게시 뒤 주소 바꾸기 + 옛 주소 넘겨주기.** 검색엔진과 공유된 링크가 깨진다. 넘겨주기 표를 두는 대신, 게시 중에는
  주소를 잠그고 내린 뒤에만 바꾸게 한다.
- **Markdown 원문 편집 칸.** 본문에 Markdown 을 붙여 넣으면 편집기가 서식으로 바꿔 준다. 원문 칸을 따로 두면 두 화면을
  맞추는 일이 생긴다.
- **함께 쓰기(동시 편집).** 두 곳에서 같은 글을 고치면 나중 저장이 충돌로 멈춘다. 그것으로 충분하다.
- **복제(바뀜).** 계획에는 있었다. 복제하면 본문의 사진까지 두 글이 나눠 쓰게 되고, 지우기 · 사진 정리 규칙이
  복잡해진다. 주소를 바꾸고 싶으면 내린 뒤 바꾸면 된다. 필요해지면 그때 더한다.
- **메뉴의 주황 점(바뀜).** 일정의 점은 「사이트가 곧 틀린다」는 뜻이다. 검토일이 지난 글은 틀린 것이 아니라 볼 때가
  된 것이라, 홈의 「블로그 글」 칸에만 둔다.

## 2. 편집기: Milkdown, 본문은 Markdown 으로 저장

**정한 것:** `@milkdown/kit` 7.23(ProseMirror + remark). 본문은 GFM Markdown 문자열로 저장한다.

**까닭 (2026-11-16 시험, `temp/wysiwyg-spike/`)**

- 저장 형식이 Markdown 이면 공개 쪽은 remark 로 그대로 그린다. 편집기를 바꿔도 글이 묶이지 않는다.
- Milkdown 은 Markdown 을 읽고 쓰는 쪽이 remark 다. 공개 사이트도 remark 다. 같은 문법 해석이라 왕복해도 글이 바뀌지
  않는다. 지운 글 54편을 다시 열고 저장했을 때 54편 모두 같은 HTML 이 나왔다.
- Tiptap 3.34(`@tiptap/markdown`, marked 기반)는 표와 줄바꿈이 다시 열 때마다 조금씩 바뀌었다. 저장 형식이 Markdown 이면
  글을 열고 닫기만 해도 손상이 쌓인다.

**굵은 글씨 뒤 조사 (꼭 고쳐야 하는 한 군데)**

- 「세율이 **25%**로 오릅니다」를 Milkdown 기본값으로 저장하면 `**25%**로` 가 된다.
- CommonMark 규칙에서 닫는 `**` 앞이 문장부호(`%`)이고 뒤가 글자(`로`)이면 닫는 표시로 보지 않는다. 그래서 사이트에
  별표가 그대로 찍힌다.
- Milkdown 이 굵게 · 기울임 변환을 자기 것으로 덮어쓰고 있어서 생긴다. 덮어쓴 것을 빼면 remark 기본 변환이 다음 글자를
  `**25%**&#xB85C;` 처럼 문자 참조로 적는다. 사이트와 편집기 모두 「로」로 읽고 굵게도 살아난다.
- 편집기 설정에서 `remarkStringifyOptionsCtx` 의 `strong` · `emphasis` 처리기를 지운다. e2e 가 이것을 지킨다(§9).

**도구줄**

- 문단 종류(본문 · 소제목 · 작은 제목), 굵게 · 기울임 · 취소선, 링크(넣기 · 고치기 · 빼기), 글머리 목록 · 번호 목록 ·
  들여쓰기 · 내어쓰기, 인용, 구분선.
- 표: 넣기(머리줄 포함 3×3), 행 · 열 더하기와 지우기, 열 정렬(숫자 열은 오른쪽). 표 안에 있을 때만 나온다.
- 사진 넣기, 사진 설명 고치기. 실행 취소 · 다시 실행.
- 단축키: Ctrl/⌘+B · I · K · Z · Shift+Z, Ctrl/⌘+S(저장).
- 제목 1 은 두지 않는다. 쪽 맨 위의 글 제목이 제목 1 이다. 붙여 넣은 글에 제목 1 이 있으면 게시 전 검사가 알린다.
- 붙여넣기:
  - 워드 · 한글 · 웹 문서의 표와 서식은 서식 그대로 들어온다(Milkdown clipboard).
  - Markdown 글은 서식으로 바뀐다.
  - 사진 파일은 올린 뒤 그 자리에 들어간다.

## 3. 데이터

`src/lib/content/schema.ts` 의 `MIGRATIONS` 에 두 번째 이전을 더한다. 더하기만 한다.

```sql
CREATE TABLE post (            -- 관리자의 작업본. 공개 사이트는 읽지 않는다(미리 보기만 예외)
  id INTEGER PRIMARY KEY,
  slug TEXT UNIQUE,            -- 주소. 새 글은 비어 있을 수 있다(NULL 끼리는 겹쳐도 된다)
  draft TEXT NOT NULL,         -- 작업본 JSON(PostData)
  revision INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL, created_by TEXT NOT NULL,
  saved_at TEXT, saved_by TEXT,
  trashed_at TEXT              -- 휴지통에 넣은 때
);
CREATE TABLE post_public (     -- 지금 사이트에 나온 글. 공개 사이트는 이 표만 읽는다
  post_id INTEGER PRIMARY KEY REFERENCES post(id),
  slug TEXT NOT NULL UNIQUE,
  data TEXT NOT NULL,          -- 게시본 JSON(PostData 와 같은 모양)
  published_at TEXT NOT NULL, published_by TEXT NOT NULL
);
CREATE TABLE upload (          -- 사진. 파일이 아니라 DB 에 둔다(아래)
  name TEXT PRIMARY KEY,       -- 내용 sha256 앞 24자 + .webp
  width INTEGER NOT NULL, height INTEGER NOT NULL,
  bytes BLOB NOT NULL,
  original_name TEXT, created_at TEXT NOT NULL, created_by TEXT NOT NULL
);
CREATE TABLE post_event (      -- 글의 변경 기록. audit_event 와 따로 둔다(아래)
  id INTEGER PRIMARY KEY,
  post_id INTEGER NOT NULL,
  at TEXT NOT NULL, actor TEXT NOT NULL, summary TEXT NOT NULL,
  before_json TEXT NOT NULL, after_json TEXT NOT NULL   -- {draft, live, trashed} 또는 null
);
CREATE INDEX post_event_post ON post_event (post_id, id);
```

**글 기록을 `audit_event` 에 넣지 않는 까닭 (바뀜)**

- 계획은 `audit_event` 에 `ref` 칸을 더하고 kind 를 `post` 로 쓰는 것이었다.
- 관리자를 앞 이미지로 되돌리면, 옛 관리자는 kind 가 `schedule` · `faq` 뿐이라 믿고 기록 화면 · 홈에서 `post` 줄을 읽다
  깨진다. 되돌리기가 안전해야 하므로 표를 따로 둔다. 옛 관리자는 모르는 표를 읽지 않는다.
- 기록 화면은 두 표를 시각 순으로 합쳐 보인다(열쇠 `a<id>` · `p<id>`).

**글 내용을 칸이 아니라 JSON 으로 두는 까닭**

- 이전은 더하기만 하고, 앞 커밋의 공개 사이트가 같은 파일을 읽고 있을 수 있다.
- 글 정보 칸이 하나 늘 때마다 표를 고치면, 이 규칙 아래에서 이전이 계속 쌓인다.
- JSON 이면 새 칸이 생겨도 이전이 필요 없다. 옛 코드는 모르는 칸을 무시하고, 새 코드는 없는 칸을 기본값으로 읽는다.
- 목록과 검색은 글 수백 편까지 JS 에서 걸러도 충분하다.

**작업본과 게시본을 표로 나누는 까닭**

- 공개 사이트가 읽는 것이 「지금 게시된 것」 하나뿐이 된다. 상태 칸을 보고 거르다 실수할 자리가 없다.
- 「고친 내용 미게시」는 두 JSON 을 비교하면 나온다. 키 순서를 고정해 저장하므로 문자열 비교로 된다.

**PostData** (`src/lib/content/post-data.ts`. 관리자와 공개 사이트가 함께 쓰므로 공개 쪽에 둔다)

| 칸 | 뜻 | 공개 쪽 이름(`PostMeta`) |
|---|---|---|
| `slug` | 주소 뒷조각, 영문 소문자 · 숫자 · `-` | `slug` |
| `title` · `description` | 제목, 요약(목록 · 검색 결과 · 공유 카드) | 같음 |
| `category` | 법인세 · 부가가치세 · 소득세 · 세무일반 · 원천세·4대보험 · 상속·증여세 · 기타 · 업무경험 | 같음 |
| `author` | 비우면 대표 회계사 이름 | 같음 |
| `date` · `updatedAt` · `lastChecked` · `effectiveFrom` | 발행일(비우면 처음 게시한 날) · 업데이트 · 검토 기준일 · 적용 시점 | 같음 |
| `keywords` | 검색 · 관련 글 · JSON-LD | 같음 |
| `sources` | 근거 자료(이름 · 주소 · 종류 · 메모) | `sourceLinks` |
| `related` · `services` | 관련 글 주소, 연결 서비스(업무경험만) | `relatedSlugs` · `services` |
| `cover` | 표지 사진 `/uploads/<이름>` | `coverImage` |
| `taxFacts` | 「세율 · 기한 · 기준금액 · 법 개정을 다룹니다」 | (공개 안 함) |
| `body` | 본문 Markdown | `content` |

**사진을 DB 에 두는 까닭**

- 파일로 두면 볼륨 경로 · 백업 스크립트 · 복원 순서 · 빌드 스냅샷을 모두 하나씩 더 맞춰야 한다. DB 에 두면 이미 있는 것이
  그대로 사진까지 맡는다:
  - 매일 S3 백업(`backup.sh`), 30일 서버 사본, 복원 연습.
  - 빌드 스냅샷(`snapshot.mjs`). 스냅샷은 빌드하는 동안만 붙고 이미지에 남지 않는다.
- 크기: WebP 로 다시 구워 가로 1600px 이하로 줄이면 한 장에 100–300KB 다. 글 수십 편이면 수십 MB 로, SQLite 에 부담이 없다.
- DB 가 500MB 를 넘으면 파일로 옮긴다(그때 이 표의 `bytes` 를 비우고 파일 경로를 더한다).

**기본 근거 자료를 없앤다**

- 지금 `posts.ts` 는 근거를 적지 않은 글에 갈래별 법령 링크를 대신 붙이고, 「검토에 사용한 근거」라 부른다.
- 쓰지 않은 근거를 쓴 것처럼 보이게 하므로 DB 글에는 붙이지 않는다.
- 대신 편집 화면에 [갈래 기본 근거 넣기] 단추를 둔다. 넣은 근거는 글쓴이가 보고 고칠 수 있다.
- 기본 키워드(제목에서 뽑기)는 남긴다. 관련 글 고르기에만 쓰이고, 없는 사실을 말하지 않는다.

## 4. 저장의 일생

| 하는 일 | 단추 | 초안(`post`) | 게시본(`post_public`) | 사이트 반영 |
|---|---|---|---|---|
| 초안 저장 | [저장] · Ctrl+S | 바뀜 | 그대로 | 하지 않음 |
| 게시 · 변경 게시 | [게시] → 확인 창 | 바뀜(화면의 내용) | 초안을 복사 | `/` 전체 다시 그리기 + 데우기 |
| 내리기 | [내리기] → 확인 창 | 그대로 | 지움 | 다시 그리기 + 그 글 주소 데우기(→ 404) |
| 휴지통 · 되살리기 | 게시 중이 아닐 때만 | `trashed_at` | — | 하지 않음 |
| 완전히 지우기 | 휴지통에서, 확인 창 | 지움(그 글의 기록과 사진도) | — | 하지 않음 |
| 되돌리기 | 변경 기록 | 그 저장 이전의 내용 | 그대로 | 하지 않음 |

- 모든 줄이 한 트랜잭션이다. 글마다 판 번호를 본다. 다른 탭이 먼저 저장 · 게시 · 내렸으면 덮지 않고 멈춘다.
- [게시]는 화면의 내용을 저장하면서 게시한다. 저장하지 않은 변경을 따로 저장할 필요가 없다.
- 새 글: [새 글]을 누르면 늘 새 빈 초안을 만들고 그 글의 편집 화면으로 간다(바뀜). 빈 초안을 다시 열면 두 탭이 한
  글을 나눠 쓰다 이 기기 보관이 서로 덮인다. 대신 [새 글]을 누를 때, 한 번도 저장하지 않은 채 하루 지난 빈 초안을 치운다.
- 사진 정리:
  - 저장 · 게시 · 지우기로 글에서 빠진 사진은, 다른 글의 초안에도 게시본에도 없으면 그 자리에서 지운다.
  - 기록(`post_event`)에만 남은 사진은 쓰인 것으로 치지 않는다. 고객 자료가 찍힌 사진을 글에서 빼면 사이트 주소에서도
    사라져야 한다. 그 기록으로 되돌리면 게시 전 검사가 「사진을 찾을 수 없습니다」로 알린다.
  - 올리고 저장하지 않은 사진은 [새 글]을 누를 때 하루 지난 것부터 치운다.
- 완전히 지우면 그 글의 기록도 지운다. 기록에 본문이 통째로 있어서다. 「지웠다」는 한 줄만 제목과 함께 남긴다.
- 글 id 는 다시 쓰지 않는다(2026-11-16 dev 점검에서 찾음). SQLite 는 맨 끝 id 가 지워지면 그 번호를 다시 내준다. 그러면
  지운 글의 기록 · 미리 보기 주소 · 이 기기 보관이 새 글에 붙고, 새 글을 지울 때 앞 글의 「지웠다」 기록까지 지워진다.
  `createPost` 가 글과 기록에 나온 가장 큰 id 다음 번호를 직접 준다.
- 주소: 게시 중에는 잠근다(검색엔진 · 공유 링크). 내리면 다시 바꿀 수 있다. 다른 글이 쓰는 주소는 고를 수 없다.
- 게시할 때 발행일이 비어 있으면 오늘(서울)로 채운다. 게시 중인 글을 다시 게시할 때는 확인 창에 「업데이트 날짜를
  오늘로」가 있다. 본문을 고쳤으면 처음부터 켜져 있다.
- 이 기기 보관 키는 `meridian-admin:draft:post:<id>` 다. 로그아웃하면 다른 작업본과 함께 지운다.

## 5. 게시 전 검사

같은 함수(`publishIssues`)를 브라우저와 서버가 돌린다. 서버는 오류만 다시 보고, 경고는 「확인했음」을 받는다.

**오류 (게시를 막는다)**

- 제목 · 주소 · 갈래 · 요약 · 본문이 비었다. 주소 꼴이 틀렸거나 다른 글이 쓴다.
- 발행일 · 검토 기준일이 미래다. 날짜 꼴이 틀렸다.
- 「세율 · 기한 …을 다룹니다」가 켜져 있는데 검토 기준일이 비었다. 새 글은 이 칸이 켜진 채로 시작한다.
  - 계획에서는 근거 자료가 없어도 막았다. 주인이 2026-11-18 에 「근거 자료는 경고만」으로 정했다(아래 경고).
- 근거 자료 줄에 이름이나 주소가 빠졌거나, 주소가 http(s) 가 아니다.
- 본문의 링크가 http(s) · `/` · `#` 이 아니다(`javascript:` 따위). 본문 사진이 올린 사진이 아니다.
- 서버에서 한 번 그려 보고 실패했다. 본문 사진이 DB 에 없다(지워진 사진).

**경고 (확인하면 게시한다)**

- 요약이 50자보다 짧거나 160자보다 길다(검색 결과에서 잘리거나 비어 보인다).
- 검토 기준일이 120일 지났다.
- 키워드가 없다. 사진에 설명이 없다. 본문에 제목 1 이 있다.
- 본문에 사이트에 나오지 않는 HTML 이 있다(공개 쪽은 HTML 을 그리지 않는다).
- 업무경험 글인데 서비스 연결이 없다(서비스 상세에 안 나온다). 관련 글 중 게시되지 않은 것이 있다(건너뛴다).
- 근거 자료가 없다. 「세율 · 기한 …」이 켜져 있으면 문구가 더 분명하다(법령 · 국세청 안내를 적어 두라고).

## 6. 공개 사이트

- **읽기.** `src/lib/content/read.ts` 에 `getPublishedPosts()` · `getPublishedPost(slug)` · `getPostDraft(id)`(미리 보기) ·
  `getUpload(name)` 를 더한다.
  - `src/lib/posts.ts` 는 함수 이름(`getAllPosts` · `getPostBySlug` · `getRelatedPosts`)을 그대로 두고 속만 바꾼다.
    쓰는 쪽 8곳은 거의 고치지 않는다.
  - `CONTENT_DB` 가 없으면(CI · 로컬) 글이 없다. 사이트는 글 0편에서도 깨지지 않게 이미 고쳐 두었다(`3d65e2b`).
- **본문 그리기.** MDX(`next-mdx-remote`)를 걷어낸다.
  - 대신 `unified` + `remark-parse` + `remark-gfm` + `remark-rehype` + `hast-util-to-jsx-runtime` 을 쓴다.
  - MDX 는 본문의 `{ }` 를 JS 로 실행한다. 관리자 계정을 빼앗기면 공개 서버에서 코드가 돈다. 그리고 `{`, `<` 하나로
    글이 깨진다.
  - 원 HTML 은 그리지 않는다.
  - 링크는 지금처럼 안전한 것만 남긴다. 사진은 `/uploads/` 의 것만 그리고, DB 의 가로 · 세로를 붙여 밀림을 막는다.
  - 넓은 표는 감싸서 표만 옆으로 밀리게 한다.
- **글 쪽 떼기.** `/blog/[slug]` 의 본문 부분을 `PostView` 로 떼어 미리 보기와 같이 쓴다. 미리 보기가 실제와 다를 수 없다.
- **미리 보기** `/blog-preview/[id]?t=<만료>.<서명>`.
  - 서명은 HMAC-SHA256 이다. 열쇠는 `REVALIDATE_SECRET` 에서 용도를 붙여 끌어낸다. 두 앱 모두 이미 가진 값이라 서버
    설정을 늘리지 않는다.
  - 1시간 지나거나 서명이 틀리면 404 다. 매번 새로 그린다. `noindex` 이고 `robots.ts` 가 막고 sitemap 에 없다.
  - README 의 「미리 보기는 세션이 필요하다」 대신이다. 관리자 세션은 다른 호스트에 있어 공개 사이트가 읽을 수 없다.
- **사진** `/uploads/<이름>.webp`.
  - 라우트 핸들러가 DB 에서 읽어 `immutable` 로 보낸다. 이름이 내용 해시라 바뀌지 않는다.
  - 초안에만 쓴 사진도 이름을 알면 열린다. 이름은 사진 내용 없이는 알 수 없다.
  - 관리자 앱에도 같은 주소(`admin/src/app/uploads/[name]`)가 있다. 편집기가 보여 줄 사진을 공개 사이트에서 가져오면
    관리자 CSP(`img-src 'self'`)와 공개 쪽 Cross-Origin-Resource-Policy 에 막힌다. 관리자 쪽은 로그인한 사람에게만 보낸다.
  - 지운 사진은 브라우저 · 중간 캐시에 1년까지 남을 수 있다(`immutable`). 공개 쪽 Cloudflare 는 DNS 만 쓰므로 중간 캐시는
    없다.
- **다시 그리기.**
  - `/api/revalidate` 는 지금처럼 `revalidatePath("/", "layout")` 이다. 이것 하나로 쪽 · sitemap · `llms.txt` ·
    `/api/search` 가 모두 낡음 표시를 받는다(Next 16 문서 확인). 데울 쪽은 관리자가 고른다:
    - 일정 · FAQ: `/` · `/faq` · `/contact` · `/portal`.
    - 글: `/` · `/blog` · `/blog/<주소>` · `/api/search`. 나머지는 처음 방문 때 새로 그린다.
  - 메뉴의 빈 갈래 숨기기(`layout.tsx`)도 다시 그려진다.
- **게시 확인 (바뀜, 더함).** 다시 그리기를 부르고 데우기까지 끝났어도, 사이트가 새 글을 내보내는지는 따로 본다.
  - 공개 글 쪽 `<article>` 에 마지막 게시 시각을 `data-published-at` 으로 찍는다.
  - 게시 · 변경 게시: `/blog/<주소>` 가 200 이고 그 시각을 담았는지, `/blog` 에 그 글 링크가 있는지 본다.
  - 내리기: `/blog/<주소>` 가 404 이고 `/blog` 에 링크가 없는지 본다.
  - 한 번 더 해 보고도 아니면 「사이트에 반영하지 못했습니다」를 모든 화면에 남긴다(`admin.publishFailed`, 일정 · FAQ 와 같다).
- **검색** `/api/search`.
  - 모듈에 담아 두던 목록을 없애고 `force-static` 으로 바꾼다. 다시 그리기에 따라 새로 만들어진다.
  - 응답 `max-age` 를 3600 에서 300 으로 줄인다. 브라우저에 남은 옛 목록이 오래 가지 않게 한다.
- **빌드.**
  - `generateStaticParams` 는 빌드 스냅샷의 게시본을 읽는다.
  - 빌드 뒤 게시한 글은 처음 방문 때 만들어 담는다(`dynamicParams` 기본값).
  - 폰트 부분집합(`subset.mjs`)은 `CONTENT_DB` 가 있으면 게시본의 글자를 더 넣는다. 빌드 뒤 새 글자는 다음 배포 전까지
    원래 폰트 조각으로 나온다. 깨지지 않고 무게만 는다(README 결정 「폰트 부분집합」).
- **정리.**
  - `content/posts/` · `gray-matter` · `next-mdx-remote` 를 지운다. 원본이 둘이 되지 않게 한다.
  - `content-audit.mjs` 의 글 검사는 게시 전 검사로 옮겼으므로 지운다. 세무 일정 검사는 남긴다(주인 답 대기).

## 7. 관리자 화면

- **메뉴:** 「사이트 내용」 아래 「블로그 글」(`/posts`). registry 에 한 줄이다.
- **목록** `/posts`.
  - 위에 상태 거르기 · 갈래 · 검색 · [새 글].
  - 줄마다 제목(없으면 「제목 없음」), 상태 표, 갈래, 마지막 저장(누가 · 언제), 검토 기준일.
- **편집** `/posts/<id>`.
  - 넓은 화면: 왼쪽에 제목 + 도구줄 + 본문, 오른쪽에 「게시」 칸과 「글 정보」 칸.
  - 좁은 화면: 위아래로 쌓는다. 도구줄은 본문 위에 붙어 따라온다.
  - 「게시」 칸: 상태 한 줄(초안 — 사이트에 없음 / 게시됨 · 날짜 / 게시됨 · 고친 내용은 아직 사이트에 없음). 그 아래
    [미리 보기] [게시], 그 아래 작은 단추로 [사이트에서 내리기](게시 중) · [휴지통으로](게시 전) · [이 글의 변경 기록].
  - 「글 정보」 칸:
    - 주소(사이트 주소 미리 보기 포함), 갈래, 요약(글자 수와 권장 범위).
    - 날짜 넷: 「오늘」 단추. 검토 기준일은 [오늘 검토함].
    - 글쓴이, 키워드(Enter 로 더함), 세율 · 기한 확인란, 근거 자료(줄 더하기 · 위아래 · 지우기, [갈래 기본 근거 넣기]).
    - 관련 글(다른 글에서 고름), 연결 서비스(업무경험일 때), 표지 사진.
  - 본문 아래: 글자 수 · 읽는 시간(사이트와 같은 계산).
- **저장 막대:** 글에서는 [저장](초안)만 있다. 문구는 「초안을 저장했습니다. 사이트는 그대로입니다.」 게시는 「게시」
  칸이 맡고, 결과는 같은 막대가 알린다.
- **변경 기록:** 「블로그 글」 거르기와 글 하나 거르기(`?type=post&post=<id>`). 한 줄 요약은 「「제목」 — 본문 3곳 ·
  요약 고침」처럼 글 이름을 앞에 둔다. 본문은 문단 단위로 비교해 바뀐 문단만 보인다.
- **홈:** 「사이트 내용」에 「게시 N편 · 초안 M편」. 「블로그 글」 칸에 미게시 변경이 있는 글과 검토 120일 지난 글.

## 8. 지키는 것 (보안 · 운영)

- 모든 액션은 로그인과 입력을 처음부터 다시 본다. 화면을 거치지 않은 POST 도 같다.
- 사진:
  - 받는 것은 JPEG · PNG · WebP 뿐이다. 브라우저가 말한 형식이 아니라 sharp 가 내용을 읽어 판단한다. 그래서 SVG 같은
    것은 들어올 수 없다.
  - 15MB, 4천만 화소까지 받는다. 방향을 바로잡은 뒤 다시 구워 메타데이터를 모두 버린다.
  - 서버 액션 한도를 16MB 로 올린다(관리자 앱만).
- 공개 쪽 본문 그리기는 JS 를 실행하지 않고 HTML 을 그리지 않는다(§6).
- 미리 보기 주소는 1시간짜리 서명이다. 공개 사이트에 세션이나 새 비밀값을 더하지 않는다.
- DB 크기와 백업은 그대로 간다. 기록(`post_event`)은 글 저장마다 본문 전 · 후를 담는다. 수천 번 저장하면 수십 MB 가
  되므로 그때 오래된 초안 기록을 줄인다.

## 9. 시험

관리자 e2e(`admin/tests/`)에 글 시험을 더한다. 관리자와 공개 사이트를 같은 DB 로 띄우는 지금의 틀을 그대로 쓴다.

1. 새 글에 본문(굵게 + 조사, 표, 링크)과 근거를 쓰고 초안을 저장한다. 공개 `/blog/<주소>` 는 404 이고 목록에도 없다.
2. 미리 보기 주소가 초안을 그린다. 서명을 바꾸면 404 다.
3. 게시 전 검사가 빈 요약을 막고 그 칸으로 간다.
4. 게시하면 아래에 나온다. 사이트의 HTML 에 `<strong>25%</strong>로` 가 있다.
   - JS 없이 연 `/blog` 와 글 쪽, sitemap, `/api/search`, `llms.txt`.
5. 게시한 글을 고쳐 초안만 저장하면 사이트는 그대로이고 목록에 「고친 내용 미게시」가 뜬다. 다시 게시하면 바뀐다.
6. 두 탭에서 같은 글을 고치면 나중 저장이 충돌로 멈춘다.
7. 내리면 404 가 된다. 휴지통에 넣고 되살린다. 완전히 지운다.
8. GPS 가 든 JPEG 를 올리면 WebP 가 되고 EXIF 가 없다. 사이트에서 가로 · 세로가 붙은 `<img>` 로 나온다.
9. 변경 기록에서 이전 초안으로 되돌린다.
10. 로그인 없이 글 액션을 부르면 거절된다.

공개 e2e 의 블로그 시험(`blog-rendering.spec.ts`)은 글이 없으면 건너뛴다. 글이 있는지는 파일이 아니라 `/blog` 의 HTML 로
본다. CI 의 공개 e2e 는 DB 가 없으므로 글 그리기는 관리자 e2e 가 지킨다.

1. 역할 → **두지 않는다.** 관리자 한 명이 쓴다고 본다. 로그인한 사람이 게시까지 한다.
2. 「세율 · 기한」 글의 근거 자료 → **경고만.** 검토 기준일은 그대로 막는다([오늘 검토함] 한 번).
3. 세무 일정 주간 점검(`schedule-check.yml`) → **일단 그대로 둔다.** 코드의 배열만 보므로 운영 일정과 맞지 않는다는 것은
   알고 둔다.

## 12. 운영에서 손볼 것 (작음)

- 미리 보기(`/blog-preview/*`)도 HTML 이라, Caddy 의 www 블록이 `Cache-Control: public, max-age=0, must-revalidate` 를
  단다. Next 는 이 쪽에 `no-store` 를 보낸다. 경로에 공유 캐시가 없고(Cloudflare 는 DNS 만) `max-age=0` 이라 지금 새는
  곳은 없다. 블록을 고칠 일이 생기면 미리 보기는 Next 의 값을 그대로 두게 뺀다.
