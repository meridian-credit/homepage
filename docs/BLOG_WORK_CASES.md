# 업무 경험 글 쓰는 법

> 쉬운 요약: 이 문서가 요약본입니다. 더 줄일 게 없습니다.

## 이게 뭔가

「업무 경험」은 **실제로 한 일**을 적는 갈래입니다.
해설 글(판례·세액공제 같은 것)과는 읽는 목적이 다릅니다.

- 해설 글 → 「이 제도는 이렇습니다」
- 업무 경험 → 「이 일을 이렇게 했습니다」

디자인검토 #62 가 정한 틀입니다.

## 어디에 나오나

한 편을 쓰면 두 군데에 같이 섭니다.

| 어디 | 조건 |
|---|---|
| `/blog?cat=case` 목록 | 갈래가 「업무경험」 |
| 서비스 상세 아래 「업무 경험」 칸 | 「연결 서비스」에 그 서비스를 체크했을 때 |

연결 서비스를 안 고르면 목록에만 서고 서비스 쪽에는 안 붙습니다(게시할 때 경고가 한 번 나옵니다).
아무 서비스에나 붙는 것보다 안 붙는 편이 낫다고 봤습니다.

## 어떻게 쓰나

관리자(admin.meridianco.kr) → 「블로그 글」 → [새 글]. 2026-11-16 부터 글은 파일이 아니라 관리자에서 씁니다.

1. 제목과 본문을 씁니다. 본문 서식은 위 도구줄로 넣습니다. 워드 · 한글에서 복사해 붙여도 됩니다.
2. 오른쪽 「글 정보」에서:
   - **주소**: 영문 소문자 · 숫자 · 붙임표. 예) `manufacturer-bookkeeping-handover-2026` →
     `/blog/manufacturer-bookkeeping-handover-2026`. 게시하면 바꿀 수 없습니다.
   - **갈래**: 「업무경험」 ← 이것을 골라야 업무 경험 갈래로 갑니다.
   - **연결 서비스**: 갈래를 업무경험으로 고르면 나옵니다. 어느 서비스 이야기인지 체크합니다.
   - 요약 · 키워드 · 글쓴이(비우면 대표 회계사).
3. [미리 보기]로 사이트에 나올 모양을 보고, [게시]를 누릅니다.

예시 값:

| 칸 | 값 |
|---|---|
| 제목 | 제조업 A사 기장 이관 — 3년치 계정 오분류를 다시 잡은 일 |
| 요약 | 넘겨받은 장부에서 대표 급여와 법인카드가 섞여 있던 건을 어떻게 갈랐는지 적습니다. |
| 갈래 | 업무경험 |
| 연결 서비스 | 세무 기장(`tax-bookkeeping`) |
| 키워드 | 기장 이관, 계정 오분류 |

### 연결 서비스 목록

관리자의 체크 목록은 서비스 주소의 뒷조각을 저장합니다. `src/lib/constants.ts` 의 `serviceGroups` 가 원본입니다.

| 분류 | 값 |
|---|---|
| 세무자문 | `tax-bookkeeping` · `tax-adjustment` · `payroll-outsourcing` |
| 회계감사 | `audit-advisory` |
| 회계자문 | `pa` · `ipo-advisory` |
| 재무자문 | `transaction-advisory` · `valuation` |

여러 서비스에 걸치면 여러 개를 적어도 됩니다.

## 본문 차례

디자인검토가 정한 순서입니다. 이 넷을 소제목으로 씁니다.

```markdown
## 의뢰 배경
## 주요 검토
## 작성 자료
## 정리 결과
```

## 주의

- **고객사 이름을 그대로 적지 않습니다.** 「제조업 A사」, 「매출 80억대 도매업체」처럼 씁니다.
- 금액은 범위로만 적습니다.
- 계약서에 비밀유지 조항이 있으면 그 건은 아예 쓰지 않습니다.
- 사진 · 화면 캡처에 고객 이름이나 숫자가 보이면 올리지 않습니다. 실수로 올렸으면 글에서 빼고 저장하세요. 어느 글에도
  쓰이지 않는 사진은 그때 사이트에서도 지워집니다.
