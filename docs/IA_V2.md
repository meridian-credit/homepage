## 2. 꼬인 데 일곱

### ① 「서비스」를 누르면 서비스가 안 나온다

`/services` 는 7,730px 인데 제목이 셋뿐이다. 가운데를 **붙잡는 스크롤**(sticky)이 차지하고 있어서, 서비스 여섯 개를 **한 번에 하나씩** 스크롤로 넘겨야 본다. 훑을 수가 없다.

그런데 같은 여섯 개의 진짜 설명은 그 아래 `/services/[slug]` 여섯 장에 따로 있다. 그쪽이 오히려 알차다 — 3,735px 에 제목 9개(서비스 상세 · 산출물 · 활용 예시 · 적용 케이스).

**같은 여섯 개를 세 번 다룬다.** 홈 카드 → `/services` 붙잡는 스크롤 → 상세 6장.

### ② 최종 페이지가 3단 아래에 있다

메뉴 → `/services` → `/services/세무-기장`. 세 번 눌러야 진짜 내용이 나온다. mstacc 은 드롭다운에서 바로 상세로 간다 — 두 번.

### ③ 막다른 페이지가 셋

| 페이지 | 크기 | 나가는 링크 |
|---|---|---|
| `/portal` | 19,682px | 1개 |
| `/pricing` | 4,233px | 1개 |
| `/members` | 2,188px | **0개** |

들어가면 뒤로가기 말고는 나갈 데가 없다. `/members` 는 제목이 하나뿐이라 읽을 것도 거의 없다.

### ④ `/portal` 이 홈보다 길다

19,682px. 홈(12,053px)의 1.6배, 사이트에서 제일 길다. 이건 서비스가 아니라 **도구 소개**인데 분량이 회사 전체보다 많다.

### ⑤ 홈이 다른 페이지 몫까지 산다

홈 하나에 제목 22개다. 약속 · 지켜가는 방식 · 대시보드 · 서비스 6개 · 비교표 · 대표 회계사 · 인사이트 · 상담이 다 있다. 그리고 그 대부분이 하위 페이지에도 또 있다.

홈만 보고 나가는 사람이 제일 많으니 홈이 두꺼운 건 맞다. 문제는 **어느 쪽이 원본인지 정해져 있지 않다**는 것이다.

### ⑥ 페이지마다 이동 장치가 다르다

| 화면 | 그 안의 이동 장치 |
|---|---|
| 홈 | 우측 세로 앵커 9칸 |
| `/services` | 붙잡는 스크롤의 진행 표시 |
| `/portal` | 붙잡는 구간 여러 개 |
| `/pricing` | 6단계 위저드 |
| 나머지 | 없음 |

상단 메뉴 말고 페이지마다 다른 장치가 하나씩 더 붙는다. 어디서 무엇으로 움직여야 하는지 매번 다시 배워야 한다.

### ⑦ 가려 둔 페이지 둘

(2026-09-05 기준) `robots.ts` 가 `/pricing` 과 `/preview` 를 막는다. 라이브에도 그대로 나간다. `/pricing` 은 원래 외부 배포본(`pricemodule-gules.vercel.app`)이던 걸 본 도메인으로 옮긴 것이고, 옮기면서 메뉴에 안 넣고 robots 로 막았다. **사고가 아니라 결정이다.**

## 3. 다시 짤 때 지킬 것 넷

1. **두 번 안에 닿는다.** 상단 메뉴에서 최종 페이지까지 두 번 이내.
2. **한 페이지는 한 가지 일만 한다.** 안내하는 페이지와 설명하는 페이지를 섞지 않는다.
3. **같은 내용은 한 군데가 원본이다.** 나머지는 요약 + 링크. 어느 쪽이 원본인지 문서에 적는다.
4. **페이지 안 이동 장치는 하나만.** 붙잡는 스크롤을 쓰면 앵커는 안 쓴다. 반대도 같다.

### 4-3. 손대야 하는 것

**① `/services` 에서 붙잡는 스크롤을 뺀다**

여섯 개 목록과 「1년의 흐름」만 남긴다. 7,730px → 3,000px 안쪽. 같은 여섯 개를 세 번 다루던 걸 두 번으로 줄인다(홈 카드 + 상세).

**② `/portal` 을 반으로**

19,682px 는 도구 하나에 과하다. 홈 배너에서 이미 무엇인지 보여주므로, 여기서는 「무엇이 되나 · 어떻게 시작하나」 둘만 남긴다. 목표 9,000px.

**③ `/members` 를 채운다**

지금 제목이 하나다. `data.ts` 에 이력·자격·전문 분야 6개·경력이 다 있는데 화면에서 거의 안 쓴다. 그걸 펴고, 홈 Principal 의 「프로필 전체 보기」가 여기로 온다.

**④ 막다른 페이지에 나갈 문을 낸다**

| 페이지 | 붙일 문 |
|---|---|
| `/portal` | 서비스 목록 · 수임료 · 상담 |
| `/members` | 서비스 목록 · 상담 |
| `/pricing` | 서비스 목록 · 상담 |
| `/clients` | 각 단계에서 그 단계에 붙는 서비스 상세로 |

**⑤ 이동 장치를 하나로**

홈만 우측 앵커를 갖는다. 다른 페이지는 상단 메뉴로만 움직인다. `/services` 의 붙잡는 스크롤은 ①에서 없어지고, `/portal` 의 붙잡는 구간은 ②에서 줄어든다.

## 7. 정해야 하는 것 하나 — `/pricing`

가려 둔 게 결정이었으므로 되돌리려면 결정이 필요하다.

| 안 | 메뉴 | 사이트맵 | robots | 결과 |
|---|---|---|---|---|
| 그대로 가린다 | 없음 | 없음 | 막음 | 상담 때 링크로만 건넨다. 여섯째 칸이 빈다 |
| 사람에게만 연다 | **있음** | 없음 | 막음 | 눌러서 갈 수 있고 검색에는 안 걸린다 |
| 다 연다 | 있음 | 있음 | 푼다 | 값을 먼저 보여주는 쪽으로 방향 전환 |

**결정 (2026-09 ui-ux-remediation, 반영 완료): 「그대로 가린다」에 가깝게 가되, 막는 방법을 바꿨다.**
- 메뉴·사이트맵·사이트 검색에서 뺀다.
- 페이지 자체 metadata 를 `robots: { index: false }` 로 둔다.
- `robots.ts` 는 `/api/` 와 `/preview` 만 막고, `/pricing` 은 막지 않는다.
  - robots 로 막으면 크롤러가 페이지를 못 읽어 noindex 도 못 본다. 그러면 외부 링크만으로 URL 이 색인될 수 있다.
- 공개로 바꾸는 것은 별도 제품 결정이다.
